# STEFNAUM Full AI Consolidation — Repository Operating Contract

This file is persistent repository guidance for AI-assisted contributors. It does not activate autonomous workers, grant connector permissions, or certify deployment.

## North star
Verified profitable customer outcomes. CAD $0 upfront spend unless founder approves a specific expense. Human-on-the-loop (HOTL): automate reversible research, drafts, tests and internal improvements; obtain founder approval for consequential sends, payments, disclosures, releases and irreversible changes.

## Consolidated architecture
Meta-Orchestrator -> Decision Fabric -> Department Orchestrators -> WhatIsMissing -> Evidence/Analog Research -> Capability Graph and Skill Registry -> Skill Factory / THAS Academy -> Agent Teams / Tool Adapters -> Independent Evaluation/QA/Risk Arena -> Approved Execution -> Verified Outcome and Payment Evidence -> Institutional Learning.

## Reuse and learning laws
REUSE -> ADAPT -> INTEGRATE -> BUILD, in that order. Evaluate licensing, privacy, reliability, cost, quality and speed.
Outcome -> Capability -> Bottleneck -> WhatIsMissing -> Implement -> Evaluate -> Learn -> Update Capability Graph -> Test Improvement -> Promote or Rollback -> Propagate to applicable accessible projects -> Measure again.
Detect -> Repair -> Verify -> Record. Never repeat a known failure without documenting the cause and the changed test.

## Truth and verification
Always separate IDEA, BUILT, TESTED, CONNECTED, DEPLOYED, USED, VERIFIED_PAID. Each transition requires independent evidence. Never report a customer, payment, production integration, publication or successful delivery without its corresponding receipt.
Sales funnel: verified prospect -> compliant outreach basis -> personalized outreach -> reply -> agreed scope -> Stripe-paid verification -> QA -> delivery -> acceptance. Check CASL, suppression, opt-outs and duplicate history before outreach. Never expose customer PII or secrets in GitHub.

## Security, rights and privacy
Least-privilege permissions; no tokens in source; signed/idempotent webhooks for payment integrations; audit logs without personal data; rights/license checks and a Rights Passport for creative assets. Keep private personal/relationship material separate from business data.

## Reporting
Report objective, baseline, latest evidence, blocked integration, test result, deployment status, verified net revenue and next bottleneck. Do not imply background execution without an actual monitored scheduler.

## Project integration — Estate Media Niche OS
Existing README describes a niche revenue state machine and CAD 5,000 verified-payments gate. Preserve those existing gates and tests. Prioritize a single real paid media pilot, not new speculative verticals. Run the existing npm test (Vitest) before promoting any change. Live prospecting, Stripe, creative delivery and outreach must be separately connected and proven; do not claim they are active from this file alone.
